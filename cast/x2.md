# X2 — HyperCore 입금 옵션 (cast)

X2 는 독립 경로가 아니라 **R3 / R5 에 붙는 옵션**이다: 가장 안쪽 extraData 가
`HyperEVM-ONE토큰(20B) ‖ transferToCoreFor(coreRecipient, value)` 가 된다. 도착한 ONE 은 executor 가 `transferToCoreFor` 를 불러
`executor → coreRecipient → Core 시스템 주소` 로 밀어 넣고, HyperCore 가 `coreRecipient` 에 크레딧한다.

```bash
# R3 + X2 :  ONE → HyperEVM → HyperCore
FROM=0x내주소 AMOUNT=10 CORE_RECIPIENT=0x코어계정 NETWORK=testnet ./r3.sh                 # 진단
FROM=0x내주소 AMOUNT=10 CORE_RECIPIENT=0x코어계정 NETWORK=testnet SEND=1 PRIVATE_KEY=... ./r3.sh

# R5 + X2 :  BSC → ONE 허브 → HyperEVM → HyperCore  (브릿지 요청 한 번으로 두 홉 처리, ERC20 이면 최초 approve 는 별도)
FROM=0x내주소 AMOUNT=10 CORE_RECIPIENT=0x코어계정 NETWORK=testnet ./r5.sh
```

수동으로 만들려면(`cast/lib.sh` 의 `core_extra`):

```bash
EXTRA2=$(cast concat-hex "$HYPEREVM_ONE_TOKEN" "$(cast calldata 'transferToCoreFor(address,uint256)' "$CORE_RECIPIENT" "$VALUE")")   # 88 bytes
```

확인 사항 — **`lib.sh` 의 `preflight_route` 가 `SEND=1` 에서 approve 전과 브릿지 전송 직전(재견적 뒤), 두 번 점검한다.** 하나라도 어긋나면 **종료코드 4**
(`preflight: REFUSED(<코드>)`)로 멈추고 approve 도 전송도 하지 않는다. 진단 모드(`SEND` 없음)에서는 같은 점검을 **보고만** 하고 종료코드는 0 이다. RPC 오류·체인 불일치도 거절이다
(`PREFLIGHT_INCOMPLETE` / `NETWORK_MISMATCH`: 검증하지 못한 점검은 통과로 세지 않는다).

- `HYPEREVM_ONE_TOKEN.isCoreTokenIndexSet()` 가 `true`(`CORE_NOT_LINKED`) — 메인넷은 현재 `false`(`TODO(PENDING)`)라 비활성.
- HyperEVM executor 가 토큰과(메서드 체크가 켜져 있으면) `transferToCoreFor`(`0x9438568d`) 를 whitelist(`EXECUTOR_NOT_WHITELISTED`).
- `coreTransferableAmount(extraData 에 담긴 금액) > 0`(`CORE_AMOUNT_ZERO`).
- 최종 목적지(HyperEVM) 브리지 `paused()==false`(`DEST_BRIDGE_PAUSED`); R5+X2 는 허브 점검(브리지 pause, `bridgeExecutor()!=0`, 허브 페어, 허브 executor 의 `0x55fd0776`, 안쪽 extraData 길이)도 포함. 목적지 **페어**는 점검하지 않는다.
- 소스 브리지 pause·페어·extraData 길이·잔고(approve 후에는 allowance 도).
- `coreUnit`(ONE: 10¹⁰ wei) 배수로 **내림**; 나머지(dust)는 `toDest` 로 돌아온다.
- **`transferToCore(uint256)` 를 extraData 에 넣지 말 것** — executor 의 Core 계정에 크레딧되어 영구 동결.
- 도착 확인: HyperEVM 쪽 `ExtraCallExecuted(success=true)` 는 EVM 쪽 입금까지만 증명. Core 잔고는 비동기이므로
  info API `POST {"type":"spotClearinghouseState","user":"<coreRecipient>"}` 로 확인한다.
